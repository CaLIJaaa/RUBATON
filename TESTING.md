# Как мы проверяли RUBA MVP

Сверху самые свежие проверки, ниже история

## 24 ноября 2026: понятная ошибка, если квитанция чужая или её нет

В браузере нашли, откуда бралась непонятная ошибка после успешной подписи: в поле стоял номер сделки демо-бота, а запрос подписывал кошелёк пользователя. Чужие квитанции по-прежнему не выдаём. Теперь и на несуществующий, и на чужой номер API отвечает одинаково, HTTP 404, с подсказкой на русском проверить номер своей сделки и пару. Старый ответ `Receipt not found` интерфейс тоже понимает. Ошибка 409 про незакрытый пакет осталась отдельной. Поле теперь подписано «Номер своей сделки»

Что прогнали: `npm run typecheck` без ошибок, `npm run test:ui` - 122 теста прошли, API-flow и авторизация - 11 прошли. Свой файл квитанции v2, восстановленный из локального журнала, через `inspectDisclosureText` дал `valid: true`. Это локальная проверка содержимого и Merkle-пути, в сеть ничего не публиковали. Транзакций и операций с деньгами во время разбора не было

## 23 ноября 2026: выбор кошелька и зависание при подключении

Подключили Web3 Onboard 2.24.1 с injected-wallets 2.11.3. SDK собирается esbuild в один локальный ESM и при открытии страницы не грузится. Подключение кошелька, Continue и смена рынка больше не просят приватную подпись и не читают баланс сами, для этого есть кнопка «Обновить данные». Отключиться можно даже во время ожидания подписи или чтения. Отменённые попытки и поздние ответы старой сессии её не возвращают и новую операцию не ломают. События слушаем у выбранного EIP-1193 provider, а не у общего window.ethereum

- `npm run typecheck`: без ошибок
- `npm run test:ui`: 104 прошли, 0 упало. Сюда вошли 10 тестов адаптера SDK и проверки контроллера подключения и смены сессии
- `npm run test:server`: 167 прошли, 0 упало, 7 необязательных пропущены. Проверили новые статические модули и CSP. Всего в этот раз 271 тест
- Встроенный браузер без расширений: окно выбора показало, что кошелька нет, после закрытия кнопка подключения снова работает
- Обычный Chrome: окно нашло Core, MetaMask, Phantom и Rabby. После выбора Rabby SDK подключился, приложение увидело Ethereum Mainnet вместо Sepolia, показало ошибку сети и не зависло. Окно выбора открывается и закрывается повторно. Приватных подписей и транзакций с деньгами в этой проверке не делали. Подключение и отключение, зависшие запросы, смену сети и аккаунта проверили отдельно на mock provider

Ради стилей Svelte и иконок только страница обменника разрешает inline CSS и локальные, data и blob картинки. Inline JavaScript и eval по-прежнему запрещены, у страниц раскрытия и Tenderly строгая CSP осталась как была. Критичные замечания к зависимостям нового SDK закрыли, закрепив overrides для crypto-es, joi, nanoid и ws. Остальные замечания npm audit по проекту в целом этим не закрыты. Контракты и артефакты для доказательств в этот раз не трогали

## Что проверяем в восстановлении и backup

Сканер читает старые `publishZkTransition` и новые публикации с proof и атомарные, проверяет закреплённое развёртывание и режим, заголовок, receipt, calldata и событие, хеши DA и AUTH, всю историю от начала и текущий путь аккаунта. Старую точку входа нового Vault он текущим режимом не считает. Вложенные вызовы без traces, неполная история, неверный root или версия и смена канонического блока отклоняются. Сам сканер транзакций не отправляет

В backup лежит `withdrawalClaims[]` с opening, сетью, Vault, domain, владельцем, слотом и commitment. Проверяем, что amount положительный и влезает в uint96, nonce и spendNonce равны и влезают в uint64, salt ненулевой, токен правильный, чужих и повторяющихся claims нет и хеш сходится. Необязательный `recoverSigner` проверяет настоящую подпись владельца EIP-712. Черновик без подписи допустим, потому что сохраняется до кошелька. Флагам accepted и spent из JSON импорт не верит и ничего не отправляет

Отдельный помощник только для чтения на одном блоке читает `withdrawalClaims`, `spentWithdrawalCommitments` и использованные nonce. Только по ним можно отличить неопубликованный, доступный и уже полученный claim. Восстановленный аккаунт, путь и общая сумма pending **не возвращают потерянные nonce и salt**. Для выплаты нужен сохранённый opening, а для нового резервирования нужен prover

Раньше схема собиралась с такими параметрами: **245 404 ограничения, 13 public signals**, Powers of Tau `2^18` Hermez phase 1 с проверенной контрольной суммой и локальный тестовый circuit-specific setup. Это тестовый setup, а не церемония для production. Старые witness могут содержать kind8, но новые Vault, движок и API обязаны его отклонять, даже если R1CS совместим
